# ADR 0006 — ルールの正しさは Tromp の合法局面数と、着手でたどり着ける配置の数と、手作りの局面で確かめる

- 状態: 受理
- 日付: 2026-10-26
- Issue: #3
- 影響する規則: QLT-008 / QLT-007 / ARC-001

## 文脈

囲碁には兄弟の perft のような「初期局面からの手順数」の定番の公表値が無い（WORK-ORDER 第 2-2 節）。代わりに、小さい盤の**合法局面数**
（すべての連に呼吸点がある石の置き方の数）を John Tromp らの公表値と一致させる。期待値は一次資料から写し、記憶で書かない。

一次資料（2026-10-26 に取得した）:

- https://tromp.github.io/go/legal.html — 「Legal counts for all boardsizes」の n×n の表（1〜19 路）。数え方は
  「19x19 の 361 点のそれぞれを空・黒・白に塗った 3^361 通りのうち、同じ色の連のすべてが隣に空点を持つもの」。
  同じページは「取りの規則により、対局に現れうる局面はちょうど合法局面である」と書く
- 同じページの表の各行から辿れる https://tromp.github.io/go/L1.html 〜 L4.html — 1×n・2×n・3×n・4×n の表

数え方: 手番は含めない。回転・裏返しで同じになる配置も別に数える（3^(m×n) 通りから数えている）。テストはこれと同じ数え方をする。

## 決定

1. **合法局面数（数え上げ）**: 3^(m×n) 通りの置き方を全部 `Position.make` に渡し、作れたもの（呼吸点の無い連が無いもの）を数えて公表値と比べる。
   大きさは 3^(m×n) が 4,300 万以下の 19 通り: 1×1〜1×8・2×2〜2×8・3×3・3×4・3×5・4×4（`Tests/NeNeIgoCoreTests/TrompCount.swift` に値と出典）
2. **着手でたどり着ける配置の数**: 空の盤から、黒と白のどちらも続けて打てるものとして（パスがあるので）`Position.play` の手（取り・自殺手の禁止）だけで
   たどり着ける盤の配置を全部数え、同じ公表値と比べる。局面スーパーコウは 1 局の履歴の規則なので、ここでは使わない。
   大きさは点の数が 14 以下の 16 通り（2×7 まで。2×8・3×5・4×4 は配置を全部覚えるので重く、入れていない）。
   1 と 2 は別の経路（局面のファクトリと、着手）で同じ数になることを見るので、どちらかの欠陥でどちらかが外れる
3. **手作りの局面**: 1 子・大石・盤の端と隅の取り・2 つの連の同時取り（呼吸点の無い隅に打っても取れるので合法）・1 子と連の自殺手の拒否・占有・盤の外・
   単純なコウの取り返しの拒否とコウ立ての後の取り返し・2 つのコウを交互に取って 2 手前の配置に戻る手の拒否（局面スーパーコウ）・パスと連続 2 パスの終局と終局後の拒否
4. **数え方**: 手作りの終局図で、石＋地・両方に接する空点（駄目）・セキ（詰めた側が取られることも確かめる）・コミ 7.5 の勝敗と半目の差
5. **不変条件**: 5 路 40 局・9 路 10 局・19 路 2 局を、テストの中のシード付きの乱数で打ち（空点を乱数の順に試して最初に打てた手・10 回に 1 回はパス）、
   1 手ごとに「打った側の石は置いた 1 だけ増え、相手の石は取られた数だけ減る」「盤の石の数は打った数からアゲハマを引いた数」
   「文字列表現を読み直したハッシュ（全計算）が差分更新のハッシュと一致」「文字列表現の往復」を見る
6. テストは release 構成で回す（`make test` = `swift test -c release`。release でも `@testable import` は効く・ADR 0001 の X-e）。
   2026-10-26 の WSL2 では、数え上げが約 25 秒、着手の数え上げ（2×7 を含む）が約 33 秒、全体が約 35 秒（並列）

## 強制

- **active**（振る舞いのテストとして）: `make check` の `test` 段。期待値は出典から写した定数で、テストのそばに出典を書いた
- QLT-008（振る舞いの変更はテストを伴う）そのものは **planned** のまま（テストを書いたかはレビュー事項）

## 結果

- 🔴 **合法局面数のテストが、実装中に本物の欠陥を見つけた**。`Position.make` で、呼吸点が見つかったら止める塗りつぶしの印を連どうしで共有していたため、
  途中で止まった連の残りの石から始めた塗りつぶしが印の付いた石を越えられず、呼吸点のある連を「呼吸点が無い」と判定していた
  （19 通りのうち 17 で公表値より少なく数えた。例: 3×4 で 321,689 のところ 217,323・4×4 で 24,318,165 のところ 15,000,743）。連の石を全部たどる別の塗りつぶしに直して 19 通りすべてが一致した。
  手作りの局面だけでは見つからなかった形の欠陥である
- 着手の数え上げが公表値と一致したことで、「取りと自殺手の禁止だけで、合法局面のすべてに、それだけにたどり着く」ことを、2×7 までの 16 通りで確かめた
- 🔴 確かめていないこと: 19 路での合法局面数（数え上げは不可能）。三コウそのものの局面（2 つのコウの循環で、直前でない配置への戻りを拒むことを確かめた。
  三コウも同じ「前に現れた配置への戻り」で止まるが、その局面は作っていない）。終局が必ず来ること（プレイアウトの方針が要るので Phase 3-2）
- ゲートの時間が約 35 秒増える

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 期待値を記憶や二次資料（解説記事・OEIS の転記）から書く | 施主の指示で禁止。一次資料（Tromp の公表ページ）から写した |
| 正方形の盤（1〜4 路）だけを数える | 4 つの値しか確かめられない。長方形の表も同じ一次資料にある |
| 数え上げを 3^12 以下に絞って速くする | 欠陥は 2×3 でも出たが、大きい盤ほど形が増える。ゲートの件数を黙って下げない。約 25 秒は受け入れる |
| 着手の数え上げに 2×8・3×5 を入れる | 2×7 で約 33 秒・約 470 MB。2×8 は配置が約 9 倍で、ゲートの時間とメモリに見合わない（2×8・3×5・4×4 は 1 の数え上げが確かめる） |
| 乱数の対局の手数の上限を置かない | このテストの目的は 1 手ごとの不変条件で、終局ではない。乱数で自分の眼を埋めるので、終局まで打つと長い（終局は Phase 3-2 の方針で確かめる） |
