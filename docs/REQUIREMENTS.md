# 要件と施主の決定 — NeNe Igo

> Status: normative（規範）/ 2026-10-26 初版
> 施主（hide）が言ったこと・決めたことだけを書く。**施主が言っていない機能を要件に書かない・実装しない。**
> 施主から後で違う指示が来たら、それに従って変え、ADR で置き換える。

NeNe Igo は、WSL2 の Ubuntu の端末（Windows Terminal）で、黒と白の手作りの囲碁 AI が延々と打ち続けるスクリーンセーバーである（Swift 製）。
1 局が終わったら次の局を始め、`q` を押すまで続く。施主の言葉は「nene-gambit, nene-reversi にならって囲碁のものを作って欲しい」。
チェス版の [NeNe Gambit](https://github.com/hideyukiMORI/nene-gambit)・リバーシ版の [NeNe Reversi](https://github.com/hideyukiMORI/nene-reversi) と同じ形
（サイバー HUD・12 テーマ・4 名のキャストの減らず口・終局後の秒読み・`install.sh` の 1 行で入る配布）を、囲碁で、新しいキャストで作る。
スクリーンセーバーに要るのは強さではなく「見ていて飽きない対局」である。

## 1. 要件（FR）

FR の番号は兄弟とそろえた。

| ID | 要件 |
| --- | --- |
| FR-01 | 端末に **19 路盤**を描き、黒と白の AI が 1 手ずつ交互に打つ様子を見せる（黒が先手・置き石なし） |
| FR-02 | ルールを完全に扱う: 呼吸点・石の取り上げ（複数の連の同時取り）・**自殺手の禁止**・**同一局面の反復の禁止（局面スーパーコウ。単純なコウはこれに含まれる）**・パス・**連続 2 回のパスで終局**。正しさは公表値との一致と手で作った局面でゲートで確かめる |
| FR-03 | AI は**モンテカルロ木探索（MCTS・UCT）＋ランダムプレイアウト**で手を選ぶ（囲碁ではアルファベータ探索が向かないため） |
| FR-04 | **終局と勝敗**: 連続 2 回のパスで終局し、**中国ルールの数え方（盤上の石＋その色だけに囲まれた空点）・コミ 7.5** で勝敗を決める（引き分けは起きない）。AI は打てる意味のある手が無くなるまで打ち切るので、死に石の判定は行わない。結果（例 `B+3.5`）を見せ、**次の局を自動で始める** |
| FR-05 | **毎回違う対局になる**（序盤の数手のばらつき・同点の手から乱数で選ぶ・プレイアウトの乱数） |
| FR-06 | 黒と白で強さや性格を変えられる（プレイアウト数・探索の定数・プレイアウトの手の好み）。勝ち負けにばらつきを出す |
| FR-07 | 石は文字ではなく、**盤とは別の色で塗った偶数桁のブロック**で描く。黒石と白石の色はテーマが決める。字形を使わないので、表示の切り替えは無い。石は**交点**に置く（盤の線と星の描き方は ADR で決め、実機の画面写真で確かめる） |
| FR-08 | `q` で終了する。どんな終わり方でも端末を必ず元に戻す |
| FR-09 | 動作環境: WSL2 の Ubuntu＋Windows Terminal |
| FR-10 | 盤の横（HUD）に、直近の棋譜数手・通算の勝敗（黒勝ち / 白勝ち）と局数・手番と手数・黒白の性格名・**取った石の数（アゲハマ。黒 n・白 n）とコミ**を出す |
| FR-11 | 1 手の間隔の初期値は 1.0 秒・終局後に結果を見せる時間の初期値は 3 秒。起動オプションで変えられる（兄弟で施主が決めた値） |
| FR-12 | 12 テーマは兄弟の 12 種類（名前と配色の方針）を引き継ぎ、盤（碁盤の地・線・星）と石の色を囲碁用に足す |
| FR-13 | カラーテーマは 12 種類くらい。実行中のキー（`t`）で切り替え、起動時は `--theme <名前>` で選ぶ |
| FR-14 | 対局中に各キャラクターが感想やリアクションを言う。英語で、ウィットに富んだブラック、ニヤッとしてしまうもの。キャストは 4 名（性格）で、局ごとにランダムに組む。セリフは 1 人 50 本。**キャストは Gambit・Reversi とは別の新しい 4 名** |
| FR-15 | キーのヘルプを画面のどこかに常に出す |
| FR-16 | 画面は Gambit の B 案（罫線の枠）と同じ構成。直前の手は、打った石を `[ ]` で囲む・端末の大きさで 2 段の配置・終局後は次の局までの秒読み。罫線が 2 桁で描かれる端末では自動で ASCII の枠に落とす |

## 2. 施主の決定（2026-10-26）

| # | 論点 | 状態 |
| --- | --- | --- |
| Q1 | アプリ名 | 決定: NeNe Igo（`nene-igo`）。「Go」だけだと Go 言語と紛らわしいため。README では「Go (igo)」と書いてよい |
| Q2 | 公開範囲とライセンス | 決定: PUBLIC・MIT |
| Q3 | 中身 | 決定: 兄弟と同じ形（スクリーンセーバー・サイバー HUD・テーマ・キャストの減らず口）・新しいキャスト。AI は外部のエンジン・ライブラリ（GnuGo・KataGo・Leela 等）を使わず一から書く |
| Q4 | 盤の大きさ | 決定: **19 路**（固定。13 路・9 路の切り替えは作らない）。テストで小さい盤を使うのは自由で、Core は盤の大きさを引数で持ってよい |
| Q5 | AI と数え方 | 決定: **MCTS＋中国ルール（盤上の石と地を数える）・コミ 7.5**。打てる所が無くなるまで打ち切るので死に石の判定が要らない |
| Q6 | 石・直前の手・HUD・キー・演出 | 決定（兄弟の推しを引き継ぐ）: 石は色のブロック（FR-07）・直前の手は `[ ]`・キーは `q` と `t` だけ・FR に無い演出は足さない（思いついたら施主に提案する） |
| Q7 | 新しいキャスト 4 名 | 決定（推し）: 実装側が決める。Gambit（VEX.EXE / MORT.SH / NULL_PTR / GRANNY.DLL）・Reversi（FLIP.BAT / CORNER.SYS / SPAM.EML / LAZY.CRON）とは違う名前・違う性格にし、`ファイル名.拡張子` 風の名前と顔文字という作法はそろえる。指し方の違いと勝敗のばらつきは計測して ADR に書き、決めたら施主に知らせる |
| Q8 | 道具の導入 | 決定: 開発用の道具は確認を待たずに入れてよい。製品の依存は CODING_RULES 第 5 節の 3 点で管理する |
| Q9 | 進め方 | 決定: フルゲートが緑なら、Ready・squash merge・Issue の起票は確認なしでよい。Release の公開など外に出る操作は確認を取る |
| Q10 | v0.1.0 の公開 | 決定（2026-10-26）: 施主が「囲碁は最後まで走り切って」と言い、確認の質問に「Release まで出してよい」と答えた。v0.1.0 を 2026-10-26 に公開した（main `711f47c`・成果物の SHA-256 `639c0601d5f2e6775a9bda471a45143ead63a48657b467fa6f5c13b268ea697b`）。以後の版の公開は Q9 のとおり確認を取る |

### 施主に聞いてから決めること（実装側で決めない）

| 論点 | いまの既定 | 聞く時期 |
| --- | --- | --- |
| 投了（勝率が低いと AI が投げる）を入れるか | **入れない**（施主は言っていない） | Phase 3 の MCTS の計測で、1 局が長すぎる・終盤の駄目詰めが退屈だと分かったら、数字を添えて施主に提案する |

## 3. やらないこと

- 施主が言っていない機能（投了・人間との対局・盤の大きさの切り替え・置き碁を含む）
- 外部の囲碁エンジン・ライブラリを使うこと
- 公表値（合法局面数）を記憶で書くこと・ゲートで回す件数を黙って下げること
